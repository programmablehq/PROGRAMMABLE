# Ethereum profile 3.6 trading

The current profile 3.6 native30 policy charges 30 basis points (0.3%) on Programmable's Ethereum routes. Historical signed policies retain their recorded rates. A buy transfers `floor(funded ETH input * 30 / 10000)` to the fixed Treasury before swapping the remaining input. A sell uses Uniswap V4 `TAKE_PORTION` on native output credit, then delivers the net output. These charges do not establish a fee on external routes.

A pool that independently proves the current 30-bps fee can waive the additional routing charge. The server checks the exact reviewed runtime, immutable pool binding, recipient and current module code, then proves the actual callback, fee ledger increment and native ERC-6909 backing. A getter or applicant declaration cannot waive the fee. Historical fee100 policies and their immutable obligations remain separate; a 30-bps pool does not satisfy a 100-bps obligation.

The classification boundary is Ethereum block `26142122`, hash `0x823e99cec0bb5b6011afc44891a1fd897b7efcbd83658cb9bc176dc35f5f86a3`. This block was finalized before any profile 3.6 authorization. Its hash was independently read through dRPC and QuickNode. Stamps at or before the boundary retain their existing route. Later stamps require a canonical finalized API record that matches the full stamp coordinates. After a successful canonical join, the website saves the verified classification in the existing private Blob store under its immutable launch identity and policy hash. Reads revalidate that identity and policy, so a server restart or metadata API outage does not disable previously verified routes. Advancing finalized checkpoints do not invalidate the record. New classifications require a successful durable write; missing, conflicting or inconsistent records keep preparation pending and never select a free route.

The website must publish this reader and fee implementation before the API selects profile 3.6. A version selection or successful launch alone is not fee-execution evidence. Actual mainnet deployment, trading and claim receipts remain separate release evidence. Historical signed fee obligations remain unchanged.

Focused checks cover exact buy/sell encoding, policy substitution, missing classifications and runtime drift. Read-only Ethereum traces through both providers additionally exercised the actual router for buy/sell, Treasury as trader and pre-existing native router dust. Those traces use state overrides and are not broadcast transaction receipts.
