# Model context

The stored intent remains the complete authority for requirements, exclusions, open choices and provenance. `planning-context.ts` projects that state into model input without changing a stored revision. Every rule ID, text, kind and open choice remains present. Original quotes and the change log stay in the account store instead of being repeated in each prompt. The latest user messages still supply the quotes required for an actual edit.

Ordinary explanations of a checked draft receive its source hash, checked requirements and fee examples. Technical source-inspection requests receive the exact source. The selection is a cost hint; it cannot request a build, alter rules or authorize anything. Older drafts that lack a complete checked behavior record keep their full source context. The source generator always receives the full saved source.

The synthetic reference with a 20,021-character source measured 47,660 system characters before the projection and 27,897 after it. The response schema stayed 3,597 characters and the question stayed 74. This is a local input-size measurement, not provider billing or a latency percentile. A 64-rule case checks that all decisions and the original intent revision survive the projection.

Actual provider qualification, representative latency and cost measurements remain separate. This projection does not shorten arbitrary code inspection, change retry or repair counts, raise the provider limit, or enable another execution path. A future general contract adapter must pass its own complete saved state through the same ownership and revision checks.
